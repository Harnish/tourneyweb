# Follow Tournaments, Levels and Teams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Registered users follow tournaments, levels and teams; followers of a level or team get an inbox+email alert with the final score when a game becomes official; followers rank first in the slot user search.

**Architecture:** One `follows` table behind new `mydb.DB` methods (Postgres + FakeDB). A single `notifyFollowers(before, after, scorerID)` helper compares the game's *official result* before and after a score write and is called from the three score paths. Follow/unfollow handlers, a Following page, tournament-list search and an HMAC unfollow link sit on top.

**Tech Stack:** Go, httprouter, html/template, database/sql + pgx, gorilla/csrf, existing `notifyUser`.

**Spec:** `docs/superpowers/specs/2026-10-17-follow-design.md`

## Global Constraints

- Every new DB method goes in the `mydb.DB` interface (`mydb/db.go`), `*MyDB` and `*FakeDB`. Schema is idempotent in `pgtables` (`mydb/mydb.go`). Postgres tests are opt-in via `TEST_DATABASE_URL='postgres://postgres:pw@localhost:55432/tourneyweb?sslmode=disable'` (podman container `twpg`).
- Follow `kind` ∈ `tournament`, `division`, `team`. Cap 50 follows per user. Draft (non-`published`) tournaments, and divisions/teams in them, cannot be followed (404).
- Alerts only when the official result changes (spec "Builder's calls"); never for `reported` or `disputed`.
- Mute: new column `users.mute_follow_alerts` (separate from `mute_score_notices`), second profile checkbox.
- All POST routes sit behind the global CSRF middleware; templates use `{{.CSRFField}}`.
- Commits conventional, end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never commit without user confirmation of the approach (user has approved per-task commits on the branch).
- Work in a git worktree on branch `feat/follow` (`../tourneyweb-follow`).

## Review Focus

- A user following both a division and a team in a game gets exactly one alert (test in Task 2).
- Staff re-saving an official game with the same score sends no alert; changing it sends "Game score corrected" (Task 2).
- A coach's first report, and a disputed game, send no follower alert; the second coach's confirming report alerts everyone except that coach (Task 2).
- `next` on follow/unfollow cannot redirect off-site (Task 3).
- A tampered or other-user unfollow token changes nothing; a GET never unfollows (Task 3).
- Deleting a team/division/tournament removes its follows (Task 1).
- Slot search followers beyond the first 10 alphabetical matches still appear first (Task 5).
