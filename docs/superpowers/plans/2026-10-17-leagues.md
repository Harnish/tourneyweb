# Leagues Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A league is a long-running tournament (same levels, teams, games, scoring) with start/end dates, a roster that locks when the season starts, reschedule notices to coaches and followers, its own home-page section, and a "Create playoff tournament" button that copies levels and teams in standings order into a linked tournament.

**Architecture:** Add `kind`, `end_date`, `league_id` columns to `tournaments`; every existing screen and permission keeps working because a league *is* a tournament row. Tournament lists filter to `kind='tournament'`; a new Leagues query feeds a new home-page section. Roster lock and reschedule notices are small handler-level additions; the playoff copy is one handler built on existing DB methods.

**Tech Stack:** Go, httprouter, html/template, database/sql + pgx, existing `notifyUser`, follows (#29).

**Spec:** `docs/superpowers/specs/2026-10-17-leagues-design.md`

## Global Constraints

- Every new DB method goes in the `mydb.DB` interface (`mydb/db.go`), `*MyDB` and `*FakeDB`. Schema is idempotent in `pgtables` (`mydb/mydb.go`). Postgres tests are opt-in via `TEST_DATABASE_URL='postgres://postgres:pw@localhost:55432/tourneyweb?sslmode=disable'` (podman container `twpg`).
- `kind` is `tournament` (default, all existing rows) or `league`; it cannot change after creation. Playoffs are `kind='tournament'` with `league_id` set.
- "Started" means `start_date <= today` using the server's local date; the start day counts as started.
- Drafts (unapproved leagues and playoffs) never appear in lists or search and cannot be followed or alert anyone (existing behavior; do not weaken it).
- POST routes sit behind the global CSRF middleware; templates use `{{.CSRFField}}`.
- Commits conventional, end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Work in a git worktree on branch `feat/leagues` (`../tourneyweb-leagues`); the user approves per-task commits on the branch; never merge or push without the user's confirmation.

## Review Focus

- A started league refuses new teams on the manage form without the override, on the legacy `/admin` form always, and the override works only for the league's own directors and site admins, never staff (Task 3).
- Another tournament's director and the league's staff cannot create a playoff (Task 5).
- The playoff copy contains levels and teams only: no games, scores, news, umpire or role assignments, no coach/staff accounts; only the creator and the league's directors become directors (Task 5).
- Leagues never appear in the tournament lists, drafts never appear anywhere public, playoffs do appear once published (Tasks 1, 2).
- A reschedule notice goes out only when start time or field actually changed, only for leagues, and never to the editor or twice to one person (Task 4).
- League creation refuses a start date in the past and an end date before the start (Task 2).
